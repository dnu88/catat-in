Read-only inspection of the working tree at `/home/Danu88/apps/kaswise`, active application `apps/mobile`. Only this audit document was written; no code changes, tests, build, deployment, database reads/writes or live UI verification. The working tree already contains unrelated modifications. ## Concrete source inconsistencies / review handles

These are source findings, **not assumed live UI defects**.

1. **Appearance choice vs effective appearance.** Settings offers and persists Dark/System, `settings.tsx:1153–1166`; theme provider persists chosen preference, `src/theme/theme-context.tsx:53–59`, but operational resolver unconditionally returns light, `src/theme/mobile-theme.ts:6–15`. The light-first policy is intentional and must remain. Proposed correction: truthful preference copy/availability, not a new dark theme.
2. **“Categories & budgets” vs expense-only envelope destination.** Link `settings.tsx:44–46`, filtered category options `budgets.tsx:608–611`, envelope-focused create/edit `:849–864`. Category service CRUD/type support does not supply a full user-facing income/expense manager by itself. Proposed: adjust scope description or explicitly design the broader manager, without assuming parity is required.
3. **Budget editor changes shared category visuals.** `budgets.tsx:680–684` updates the selected category's icon/color and sets `visual_locked_by_user: true` before saving envelope `:686–700`. These are not purely local envelope appearance changes. Category write can succeed before an envelope save fails; this is a source-level partial-update possibility, not evidence it occurred. Proposed: explain shared impact and design save scope deliberately.
4. **ID/EN settings vs untranslated destination content.** Language choices `settings.tsx:1414–1436`; import strings remain Indonesian across picker/preview/confirm `imports.tsx:241,301–363`; help data is Indonesian `src/content/legal-pages.ts:21–44` and renderer has no i18n selector `src/components/legal/LegalInfoScreen.tsx:9–12`. Proposed: align public destination copy with existing app locale before adding more preference controls.
5. **Notification switches can visually diverge after a failed save.** Optimistic local changes plus `.catch(() => {})`, `settings.tsx:633–661`. Proposed: feedback/rollback/retry policy. No runtime network failure was reproduced.
6. **Same finance context, different selection presentations.** Shared component supports dropdown/sheet + optional host change guard, `src/components/FinanceContextSwitcher.tsx:15–29,42–52,126–137`. Settings uses compact/default dropdown `settings.tsx:1609`; Capture requests sheet `capture.tsx:2165`. Dropdown trigger is capped at 132px with single-line active label; sheet widens and permits two lines, `FinanceContextSwitcher.tsx:72,146–156`. This is a concrete structural difference; truncation/overflow on a real device was not tested. Proposed: consistent context identity/value legibility; retain Capture guard and sheet where needed.
7. **Static help has internal rollout wording.** “Track A saat ini…” at `src/content/legal-pages.ts:42` does not match the public, bilingual, user-oriented support surface. Voice-capable source is conditional, so this audit does not label help's current feature claims false in production. Proposed: user-facing, capability-aware tutorial/help copy.

## Optional adaptation priorities, not a delivery plan

- **First: truth and coherence.** Preference/effective-theme wording; category-link scope; translated help/import labels; notification persistence feedback; clarify shared category visual changes.
- **Second: transferable presentation craft.** Quieter grouped Settings, real trailing active values, editor preview and less fragmented icon/color controls, deliberate category detail/empty-state hierarchy. Build on current tokens and controls.
- **Separate product decisions, not visual-polish obligations:** CSV export, Apple Shortcuts, dedicated category manager/detail history, recognizer-language selection, multi-image camera capture, net-worth/fixed-assets modeling, interactive tutorial completion.
- **Already implemented—do not recreate:** grouped Settings branches, ID/EN selection, import preview/confirm, expense-envelope progress/cycles, saved report periods, Home amount visibility, wallet type filtering, finance-context selection, notification inbox, text/photo/conditional voice Capture.
