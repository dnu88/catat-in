### 3. Audit-log design for next implementation slice

Recommended audit table shape for a later migration:

```sql
create table public.security_audit_events (
  id uuid primary key default gen_random_uuid(),
  event_at timestamptz not null default now(),
  actor_user_id uuid null references auth.users(id) on delete set null,
  household_id uuid null,
  entity_table text not null,
  entity_id uuid null,
  action text not null check (action in ('insert', 'update', 'delete')),
  changed_fields text[] null,
  before_data jsonb null,
  after_data jsonb null,
  request_id text null,
  source text not null default 'db_trigger'
);
```

Recommended trigger targets, in priority order:

1. `transactions`
2. `wallets`
3. `budget_envelopes`
4. `budgets`
5. `profiles` for billing/profile-management fields only

Implementation notes:

- Use `security definer` trigger functions with a fixed `search_path`.
- Keep audit rows append-only.
- RLS for app clients should be read-only or disabled from direct client access; service role/backend can read for support investigations.
- Do not store secrets, auth tokens, raw payment credentials, or large receipt payloads.

### 4. Rate-limit Phase 2 plan

Current backend has config placeholders:

```text
RATE_LIMIT_DEFAULT
RATE_LIMIT_AI_ENDPOINT
```

Recommended next step is proxy/Redis-backed limiting rather than in-memory limiting, because production may be restarted/recreated and should not depend on process memory. Suggested policy:

| Surface | Suggested starter limit | Key | Notes |
|---|---:|---|---|
| `/health` | lenient / no strict limit | IP | Keep uptime checks safe |
| `/api/v1/ai/*` | 20/min | user id + IP fallback | High cost/risk |
| `/api/v1/imports/*` | 10/min | user id + IP fallback | Upload/parse risk |
| Supabase Edge Functions | 20/min | user id + IP fallback | Mirror backend AI limit |
| Auth endpoints | Supabase-managed + proxy WAF | IP/email | Avoid custom auth lockout bugs |

### 5. CSP reduction plan

Live PWA currently needs `unsafe-inline` for Expo/Metro runtime injection and styles. Do not remove abruptly. Reduction path:

1. Inventory inline scripts/styles generated by current PWA export.
2. Move runtime Supabase config injection to a nonce/hash-compatible script.
3. Test Expo Router web boot with nonce/hash CSP in staging.
4. Remove `unsafe-inline` only after Lighthouse/manual auth/PWA smoke remain green.
