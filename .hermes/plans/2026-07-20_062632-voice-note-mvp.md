# Voice Note MVP Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Menambahkan fitur voice note untuk mencatat transaksi lewat rekaman suara tanpa mengganggu Capture AI live, dengan default feature flag OFF dan review-before-save.

**Architecture:** Mobile merekam audio pendek, mengirim audio ke backend endpoint baru, backend melakukan transkripsi melalui provider adapter, lalu memakai extractor transaksi teks yang sudah ada. Backend mengembalikan transcript + draft transaksi; mobile menampilkan review dan memakai flow `createTransaction` existing untuk save. Fitur tidak auto-save di MVP.

**Tech Stack:** Expo Router, React Native, TypeScript, `expo-av` existing dependency, FastAPI, provider adapter untuk transcription, existing `extract_transaction_from_text`, Jest/pytest.

## Safety Principles

1. **Feature flag default OFF.** No voice UI in live default build.
2. **Review-first.** Voice result should show transcript + draft before user saves.
3. **Reuse text extraction.** Do not build separate financial parser for voice.
4. **Provider adapter.** Backend must degrade safely if transcription env key is missing.
5. **Strict upload limits.** Audio max duration/size/mime validated on client and backend.
6. **No persistent audio in MVP unless required.** Direct upload to backend is simpler and reduces cleanup risk.
7. **Do not alter existing text/photo Capture behavior.** Add code behind flag only.

## Task 4: Add `/api/v1/ai/voice` endpoint

**Objective:** Accept audio upload, transcribe, reuse text extraction, return draft response.

**Files:**
- Modify: `backend/app/api/v1/ai.py`
- Test: `backend/tests/test_ai_voice.py`

**Endpoint shape:**

```py
@router.post("/voice", dependencies=[Depends(rate_limit_ai)])
async def analyze_voice_note(
    request: Request,
    file: UploadFile = File(...),
    current_user=Depends(get_current_user),
):
    ...
```

**Validation:**

- content type in allowed audio set,
- size <= `VOICE_MAX_UPLOAD_SIZE_MB`,
- auth required,
- rate limit dependency enabled.

**Entitlement decision:** MVP should reuse `kind="chat"` quota, because output is equivalent to text extraction. This avoids schema changes for voice counters.

Implementation sequence:

1. Load entitlement state.
2. Evaluate `kind="chat"`.
3. Read upload with voice size limit.
4. Call `transcribe_audio`.
5. If transcript length < 2, return 422.
6. Call `extract_transaction_from_text(transcript)`.
7. Record chat use only when result has transactions, matching `/chat` behavior.
8. Return:

```json
{
  "transcript": "...",
  "transactions": [...],
  "unclear": null
}
```

**Important:** Do not auto-insert transactions in backend.

**Tests:**

- unsupported content type returns 415,
- too large returns 413,
- no quota returns 402/429 same as chat,
- provider missing returns 502 with friendly detail,
- success calls text extractor with transcript,
- success records chat usage if transactions found.

Run:

```bash
cd backend && python -m pytest tests/test_ai_voice.py tests/test_ai_gating_chat.py -q
```

Expected: PASS.

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Voice mishears amount | Review-first; show transcript before save. |
| Provider key missing in production | Endpoint returns 502 friendly; feature flag OFF by default. |
| Audio upload too large | Client + backend limits; max duration 60 sec. |
| PWA microphone incompatibility | Canary test on iPhone/mobile browser before broad release. |
| Capture screen complexity grows | Extract voice service/hook; avoid inline provider logic. |
| Quota semantics unclear | Reuse chat quota in MVP; add separate voice counter only if needed later. |
| Existing tests assert no Rekam | Keep flag OFF default and add flag-ON tests separately. |

## Open Questions Before Execution

1. Should voice be premium-only or share chat quota for all users? Recommended MVP: share chat quota, but hide behind canary flag.
2. Which transcription provider key is available on VPS? Recommended: OpenAI transcription if API key is available.
3. Should audio be deleted/persisted? Recommended MVP: direct upload to backend, no persistence.
4. Should voice save `input_type="voice"` immediately? Recommended: yes if TS types and DB schema support it; otherwise update shared type first.
